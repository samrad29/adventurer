# Phase 1 schema

The executable DDL is `migrations/sql/0002_phase1_schema.sql`. Everest is seeded by `0003_seed_everest.sql`. The legacy copy, validator, and reverse sync are `0004_copy_legacy.sql`. Alembic applies them in that order and refuses any database except a localhost database named `adventurer_migration_test`.

The Flask application reads and writes these tables. It does not run schema DDL on startup. Alembic remains responsible for schema changes, including on the isolated test database. The hosted project is not a migration target.

## Refinements

- `activities.source` and `activities.activity_type` are `NOT NULL`, defaulting to `manual` and `unspecified`.
- Verification statuses are `pending`, `verified`, `rejected`, `needs_review`, and `not_required`. A manual activity must be `not_required`. Any other source must use one of the four review statuses, so a manual row cannot be stored as verified.
- `activity_credits` has no `competition_eligibility` or `eligibility_reason`. Season eligibility is a later model.
- Expedition checkpoints have `UNIQUE (expedition_id, position)` and `CHECK (position >= 0)`, plus the earlier unique slug and elevation constraints.
- Elevation is `numeric(12, 5)` meters. A tenth of a foot times the international foot, 0.3048, is exact at five decimal places (`0.1 ft = 0.03048 m`). Distance is `numeric(14, 3)` meters. Duration is whole seconds.
- Verification events are append-only. Updates, deletes, and truncates are rejected. Deleting an activity is the one path that removes its history, through a before-delete trigger. Each event's statuses use the same domain, `from_status` must follow the previous event, and the activity's status must match the latest event at commit.
- `started_at` and `ended_at` are both null or both present, and `ended_at >= started_at`.

`competition_seasons` is created with its constraints and is not referenced by any other Phase 1 table. The migration inserts no season rows.

## Measurements

| Column | Type | Rule |
|---|---|---|
| Elevation meters | `numeric(12, 5)` | Greater than 0. Exact for foot values with one decimal place. |
| Distance meters | `numeric(14, 3)` | Null or greater than 0. Millimeter precision. |
| Duration | `integer` | Null or greater than 0. Whole seconds. |

Checkpoint and expedition target elevations use the same elevation type. Everest heights are the current foot values times 0.3048, not survey meters. The summit is `(29032 * 0.3048) = 8848.95360` m. Timms Hill is `594.81720` m.

## Tables

All tables are in the `adventurer` schema. Mutable tables have `created_at` and `updated_at timestamptz NOT NULL DEFAULT now()`, and a trigger sets `updated_at` on update. Verification events have `created_at` only. Row level security is enabled and not forced, matching the current tables. `anon` and `authenticated` are revoked from the schema, tables, and identity sequences when those roles exist. `ON UPDATE` stays the default `NO ACTION`.

### users

Preserves `adventurers.id`.

- Primary key `id bigint GENERATED BY DEFAULT AS IDENTITY`
- `username text NOT NULL`
- `username_key text NOT NULL` unique
- `password_hash text NOT NULL`

### user_profiles

- Primary key `user_id`
- Foreign key `user_id` to `users` on delete cascade
- `display_name text NOT NULL`
- `unit_system text NOT NULL DEFAULT 'imperial'` check `imperial` or `metric`

### expeditions

- Primary key `id`
- `slug text NOT NULL` unique
- `name text NOT NULL`
- `target_elevation_m numeric(12, 5) NOT NULL` check greater than 0
- `status text NOT NULL DEFAULT 'active'` check `draft`, `active`, or `retired`

### expedition_checkpoints

- Primary key `id`
- `expedition_id bigint NOT NULL` references `expeditions` on delete cascade
- `slug text NOT NULL`, `name text NOT NULL`
- `position integer NOT NULL` check `position >= 0`
- `elevation_m numeric(12, 5) NOT NULL` check greater than 0
- Unique `(expedition_id, position)`
- Unique `(expedition_id, slug)`
- Unique `(expedition_id, elevation_m)`

### expedition_participations

- Primary key `id`
- `user_id` references `users` on delete cascade
- `expedition_id` references `expeditions` on delete restrict
- `status text NOT NULL DEFAULT 'active'` check `active` or `withdrawn`
- `joined_at timestamptz NOT NULL DEFAULT now()`
- Unique `(user_id, expedition_id)`
- Unique `(id, user_id)`, so a credit can reference the participation and the user together
- Index `(expedition_id)`

### activities

- Primary key `id`, and the copy writes `logs.id` into it
- `user_id` references `users` on delete cascade
- Unique `(id, user_id)`
- `activity_type text NOT NULL DEFAULT 'unspecified'` check `run`, `hike`, `walk`, `stair_climb`, `other`, `unspecified`
- `activity_date date NOT NULL`
- `started_at` and `ended_at` nullable, with the both-or-neither check above
- `duration_s integer` null or greater than 0
- `distance_m numeric(14, 3)` null or greater than 0
- `elevation_gain_m numeric(12, 5) NOT NULL` check greater than 0
- `source text NOT NULL DEFAULT 'manual'` check `manual`, `adventurer_ios`, `apple_health`, `garmin`, `coros`, `other`
- `external_id text` null. Non-manual rows must have one. Unique `(user_id, source, external_id)`. Null external ids stay distinct, so manual rows do not collide.
- `source_metadata jsonb NOT NULL DEFAULT '{}'` and it must be a JSON object
- `verification_status` uses the domain, `NOT NULL DEFAULT 'not_required'`
- Check: manual rows are `not_required`; every other source is `pending`, `verified`, `rejected`, or `needs_review`
- `note text NOT NULL DEFAULT ''`
- Index `(user_id, activity_date DESC, id DESC)`

The default status is `not_required` because the default source is `manual`, and that pair has to be valid. An import that sets a device source and forgets the status fails the check instead of skipping review.

### activity_credits

Progress is the sum of `credited_elevation_m` for a participation. There is no eligibility column.

- Primary key `id`
- `activity_id`, `participation_id`, and `user_id` are not null
- `credited_elevation_m numeric(12, 5) NOT NULL` check greater than 0
- Unique `(activity_id, participation_id)`, so one activity can credit several expeditions and cannot credit the same participation twice
- Foreign key `(activity_id, user_id)` to `activities (id, user_id)` on delete cascade
- Foreign key `(participation_id, user_id)` to `expedition_participations (id, user_id)` on delete cascade
- Index `(activity_id, user_id)`
- Index `(participation_id, user_id)`

The composite foreign keys reject a credit that attaches one person's activity to another person's participation.

### activity_verification_events

Append-only audit history. No `updated_at`.

- Primary key `id`
- `activity_id` references `activities` on delete cascade
- `from_status` nullable, `to_status NOT NULL`, both the verification domain
- Check `from_status IS DISTINCT FROM to_status`
- A before-insert trigger requires the first event to have a null `from_status`, and every later event to start from the previous `to_status`
- A deferred constraint trigger requires the activity status to equal the latest event
- `reason text NOT NULL` and not blank
- `actor_type text NOT NULL` check `system`, `user`, `admin`, or `provider`
- `actor_user_id` references `users` on delete set null. `user` and `admin` actors must have an id. `system` and `provider` may omit it.
- Index `(activity_id, id)`
- Index `(actor_user_id)`

Direct update, delete, and truncate raise. `BEFORE DELETE` on an activity sets a transaction-local flag and deletes that activity's events, which is what makes the cascade succeed.

### competition_seasons

Schema only.

- Primary key `id`
- `expedition_id` references `expeditions` on delete restrict
- `slug text NOT NULL`, `name text NOT NULL`
- `starts_at` and `ends_at timestamptz NOT NULL`, check `ends_at > starts_at`
- `status text NOT NULL DEFAULT 'draft'` check `draft`, `scheduled`, `active`, or `closed`
- Unique `(expedition_id, slug)`

No season participation table and no season credit table.

## Legacy mapping

`adventurers` and `logs` stay in place.

| Legacy column | Destination | Rule |
|---|---|---|
| `adventurers.id` | `users.id` | Same value |
| `adventurers.name` | `users.username`, `user_profiles.display_name` | Verbatim |
| `adventurers.name_key` | `users.username_key` | Verbatim |
| `adventurers.password_hash` | `users.password_hash` | Verbatim |
| `adventurers.created_at` | `users.created_at`, `user_profiles.created_at` | Text parsed as `timestamptz`. Unparseable values abort the copy. |
| `logs.id` | `activities.id` | Same value |
| `logs.adventurer_id` | `activities.user_id` and the credit's `user_id` | Verbatim |
| `logs.challenge_slug` | Expedition slug, then one participation and one credit | See the slug rules below. Not stored on the activity. |
| `logs.elevation_ft` | `activities.elevation_gain_m` and `activity_credits.credited_elevation_m` | `(elevation_ft::numeric * 0.3048)::numeric(12, 5)`. The credit copies the full gain. |
| `logs.distance_km` | `activities.distance_m` | Null stays null. Otherwise `(distance_km::numeric * 1000)::numeric(14, 3)`. |
| `logs.happened_on` | `activities.activity_date` | Parsed as `date`. Start and end stay null. |
| `logs.note` | `activities.note` | Verbatim |
| `logs.created_at` | `activities.created_at`, the credit's `created_at`, and the opening event's `created_at` | Parsed as `timestamptz` |
| none | `source`, `activity_type`, `verification_status` | `manual`, `unspecified`, `not_required` |
| none | Opening verification event | `from_status` null, `to_status` `not_required`, actor `system`, reason stating that the manual entry is not independently verified |

Every existing account also gets an active Everest participation with `joined_at` equal to the account's `created_at`. Accounts with no logs still get that participation. Their credit total is zero.

## Identity sequences

`users.id` and `activities.id` are `GENERATED BY DEFAULT AS IDENTITY`, so the copy can insert the preserved ids. After the insert, the revision sets each sequence to `max(id)` with `is_called` true. The next id is one past the preserved maximum. When a table is empty, the sequence is set to 1 with `is_called` false, so the first generated id is 1.

Expeditions, checkpoints, participations, credits, events, and seasons do not reuse legacy ids. Their identity columns advance normally during the seed and the copy.

The isolated test preserved user ids 3, 8, and 9 and activity ids 4, 12, 15, and 16. The next generated user id was 10 and the next activity id was 17.

## Challenge slugs

An expedition's slug is the challenge slug. There is no rename table.

| `challenge_slug` | Expedition | Who is enrolled |
|---|---|---|
| `everest` | The seeded Everest expedition | Every existing account |
| Any other slug that equals an expedition slug | That expedition | Only accounts with at least one log of that slug |
| Anything else | None | The copy revision aborts and lists the slug. No copied rows are committed. |

Adding a historical slug means seeding an expedition with that same slug before the copy runs, then running the copy again. The migration will not guess.

## Rollback

Before cutover, `alembic downgrade 0001_legacy_baseline` drops the new tables and their functions. The `0001` downgrade does nothing, so `adventurers` and `logs` remain. This was tested: the legacy rows after downgrade matched the rows from before the upgrade.

After cutover, call `adventurer.reverse_sync_new_rows_to_legacy()` before relying on the old app. It inserts accounts and logs that are not already in the legacy tables, preserving their ids, and then advances the legacy identity sequences. It refuses the whole sync when a new account has no imperial profile under the same name, or when a new activity is not a single full-credit manual activity with no start, end, duration, external id, or source metadata. Provider rows and partial credits are not squeezed into `logs`.

The reverse sync inserts missing rows only. It does not copy later edits, and it does not delete a legacy log whose activity was removed after cutover. The old app would show that log again. That limit is acceptable only for a short cutover window.

Dropping `adventurers` and `logs` is not part of these revisions.

## Validation

`adventurer.assert_phase1_legacy_match()` runs in the copy transaction and aborts it on any failure. It compares:

- Count of `adventurers` to `users`, and `users` to `user_profiles`
- Count of `logs` to `activities`, and `logs` to `activity_credits`
- User ids and activity ids, both directions
- Usernames, keys, password hashes, notes, dates, and timestamps
- Elevation totals by user and challenge slug. The legacy sum of `elevation_ft::numeric` and `sum(credited_elevation_m) / 0.3048` must agree within `0.00002` feet per activity, which is the rounding bound of `numeric(12, 5)` meters.
- Checkpoint unlocks. A checkpoint is unlocked on one side and locked on the other only when the legacy foot total and the new meter total disagree around that checkpoint. The copy aborts and names the user and checkpoint.
- Identity sequences for `users` and `activities`

Re-running the function is a pre-cutover check. It expects the copied rows to still be the original manual rows.

## Phase 2 application

Account creation inserts `users`, `user_profiles`, and an active Everest participation in one transaction. Login uses `users.username_key` and `users.password_hash`. The session still stores `adventurer_id`, because the 7,000 ft trail name is a hash of that integer.

A manual log inserts an `activities` row (`manual`, `unspecified`, `not_required`), one `activity_credits` row for the full elevation, and the opening verification event. That event is required by the existing deferred constraint, which rejects an activity whose status has no matching event at commit. Elevation and distance are converted with `Decimal` at 0.3048 meters per international foot. Removing a journal entry deletes that expedition's credit and leaves the activity row in place.

Progress and the casual leaderboard sum `activity_credits.credited_elevation_m` for the participation. Checkpoint target, elevations, order, slugs, and names come from `expeditions` and `expedition_checkpoints`. Narrative text stays in `adventurer/challenges.py`.

## Deferred

- Season participation, season credits, prize eligibility, and verified-only rankings.
- Provider imports, GPS, and an activity-type picker. The log form still has no type, so new rows stay `unspecified`.
- Dropping `adventurers` and `logs`. The application does not read or write them.
- An activity library. An activity with no remaining credits stays in the database.
- Excluding rejected credits from progress. Manual rows are `not_required`, and that rule can wait until review exists.
- A multi-expedition editor. One activity can hold a second credit, and deleting one credit leaves the other, but the pages still edit a single expedition.

## What this revision does not do

Season participation, season credits, provider imports, and evidence tables are not implemented. Story text stays in `adventurer/challenges.py`.
